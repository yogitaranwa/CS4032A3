# CS4032 Cloud Computing Assessment 3: Knowledge distillation and a command parser on a local cloud

Author: Yogita Kumari, Roll number 230101091. Repository: https://github.com/yogitaranwa/CS4032A3

A teacher model (phi3.5 on Ollama) labels 3,000 voice-assistant commands in parallel shards. The cleaned labels train a
70M-parameter student (EleutherAI/pythia-70m, sequence-level distillation, CPU only). The student is served by a FastAPI
service on a local Kubernetes cluster (k3d) with SeaweedFS as object storage. Everything runs on free tools; the heavy
stages also run on free GitHub Actions runners.

```

prompts/         teacher_prompt.txt
```

## Quick start (fresh clone, three commands)

Needs Docker, k3d, kubectl, openssl and Python 3 (venv). The models come from the GitHub Release named `models`
(created by the `train` workflow), unless `out/models/v1` and `out/models/v2` exist locally.

```bash
git clone https://github.com/yogitaranwa/CS4032A3.git && cd CS4032A3
make up          # cluster, images, SeaweedFS, buckets, models, app
curl -s localhost:8080/parse -H 'content-type: application/json' -d '{"text":"what is the weather in imphal"}'
make down        # delete the cluster
```

Credentials for object storage are generated by `scripts/secrets.sh` into `.secrets/` (git-ignored) and loaded into
Kubernetes Secrets. No credential is stored in the repository.

## Run the whole pipeline on GitHub Actions

Run these from the Actions tab, in this order (each one commits its evidence files back to `main`):

| Order | Workflow | What it does | Time |
|---|---|---|---|
| 1 | `label-teacher` | 15 parallel shard jobs (200 commands each, phi3.5, temperature 0, seed 42), teacher scored on validation.jsonl, merge and clean into `datasets/v1/train.jsonl` + `train.sha256`, in-cluster demo with two workers in namespace `pipeline` | about 1 to 3 h |
| 2 | `train` | trains v1 and v2 (pythia-70m, first 1,500 records), scores both and the untrained base model, publishes `model-v1.tar.gz`, `model-v2.tar.gz` and their `.sha256` files as assets of release `models` | about 1 h |
| 3 | `deploy-and-measure` | 50-request memory test at 1 CPU / 1 GiB, `make up`, all Task 4 scenarios, standard Locust run, `make down` | about 1 h |
| any | `ci` | lint, unit tests, model evaluation from the Release, quality gate, gitleaks. Model evaluation and the gate are skipped (green) until the `models` Release exists. Run it manually with `model = untrained-base` to produce the failed quality-gate run for the report | 10 min |

## Design notes

- Sharding: a worker takes the pool lines whose 0-based line number leaves remainder `SHARD_INDEX` modulo `SHARD_COUNT`.
  Every id lands in exactly one shard. `clean.py` checks that no id is missing or repeated before it cleans.
- Rejection rules: each record is counted under the first rule it breaks, in the order (a) invalid JSON, (b) wrong keys,
  (c) intent outside the eight, (d) slot not null and not text in the command. Duplicates (e) are then removed among the
  records that passed, keeping the smallest id. So input = a + b + c + d + duplicates + kept.
- Training target: the teacher's reply is parsed and written back as compact JSON (no manual edits). Loss is computed on
  the reply tokens only.
- Model archive: `model.sha256` is the SHA-256 of the Release archive, which is built reproducibly. `files.sha256` lists
  every file inside it, and the service verifies it after download.
- The Deployment starts with 2 replicas and the HPA has minimum 1, so an idle cluster settles at 1 replica.
  `scripts/evidence.sh` temporarily pins the minimum to 2 for the tests that need exactly two replicas.

## Known limits

- The cluster is one node, so it shows Pod-level recovery but not tolerance of a machine failure.
- On a GitHub runner the load generator, Traefik, SeaweedFS and the replicas share 2 vCPUs, so latency differs from a quiet laptop (on the measured laptop the p95 was 4.4 s vs 1.5 s on the shared runner; the cause is not isolated).
- Measured numbers appear only in `results/` and the report.
